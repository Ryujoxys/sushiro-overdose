# 用户体验排查

日期：2026-09-20。代码：`4e41f82`，已获取远程状态并确认没有落后。界面实测使用 v4.0.1 macOS 发布版，业务代码对应 `c83e519`。

## 先修两项

### 1. 个人记录会被静默裁掉

优先级：P1。证据：代码确定。

`queue_baseline.jsonl` 和 `queue_observations.jsonl` 各有 100,000 行总上限。超限后直接重写文件，只保留最近的数据，不归档，界面也没有保留策略提示。记录门店越多，能保留的时间越短。这与“积累自己的记录”这个核心用途直接冲突。

建议：原始记录按月归档，不自动删除；限制聚合缓存而不是原始数据。如确需清理，先展示保留范围并让用户确认。不能把“导出近一年”当成完整备份。

代码：[上限与裁剪](../internal/app/queue_data_files.go#L25)、[原文件重写](../internal/app/queue_data_files.go#L126)、[采集写入路径](../internal/app/queue_baseline.go#L442)。

### 2. “取消这个号”与实际取消对象不绑定

优先级：P1。证据：代码确定，纯模拟确认取消请求体为 `{}`，未执行真实取消。

页面显示 A 号后，如果用户在小程序换成 B 号，或在应用中更换账号，旧卡片仍可能留在页面。点击“取消这个号”时，服务端使用最新凭证，取消该账号当时的当前号码，没有核对用户看到的卡片。

建议：换账号立即清空旧卡片；取消前重新查询，确认框展示账号、门店和号码，提交预期对象并核对，不匹配则拒绝。官方接口只按账号取消，不能宣称本地核对能消除所有并发变化风险。

代码：[空取消请求](../internal/app/webui/auth_ticket.js#L77)、[服务端读取最新凭证](../internal/app/web_engine.go#L697)、[断开账号未清卡片](../internal/app/webui/app.js#L251)。

## 流程检查

| 步骤 | 流程 | 当前情况 | 最值得改的地方 |
|---|---|---|---|
| 1 | 首次打开、选店 | 能看到真实历史，但下一步不突出 | 把选店和开始记录提到首屏，区分查看门店与记录门店 |
| 2 | 开始记录、日常后台 | 控制入口存在；本轮未启动真实采集 | 明确暂停与彻底退出，检查升级后的自启动目标 |
| 3 | 查看曲线、导出 | 曲线可读，历史来源已标注；导出易误解 | 明确当前筛选范围，避免空导出，提供完整备份 |
| 4 | 看实时排队、手动取号 | 公共排队可读取、确认步骤清楚 | 处理陈旧实时数据，以及取号前不起作用的路程输入 |
| 5 | 连接账号、失败恢复 | 有明确断点，未验证真实认证 | 修手机说明、停止入口、验证失败与查询恢复 |
| 6 | 设置、升级与退出 | 基本入口简洁，但本地应用管理不完整 | 增加全部记录备份/恢复和退出后台，不再堆新功能 |

本轮已展示原生窗口的首屏、下方记录区、选店搜索、保存后状态、手动取号、目标用餐时间、确认弹窗、认证入口和设置截图。截图在本次对话中，未用旧 README 图片代替；本报告只保存文字与代码索引。

## 逐项改进

### 首屏把开始记录放在前面

优先级：P2。证据：原生窗口实测与代码。

默认窗口第一屏被指标、筛选和大图表占满，“选择门店”和“开始记录”需要下滚。保存“罗湖益田假日广场店”后，图表仍显示“东方宝泰店”，顶部又显示“记录 1 家店”，但实际尚未开始记录。

建议：新用户顶部先显示“选常去的店”和一个主按钮；首次保存后显示“尚未开始”，引导到开始按钮，并切换至刚选的门店。不要擅自开始后台或自启动。历史曲线仍保留，只是让位给第一步。

代码：[页面顺序](../internal/app/webui/index.html#L28)、[图表门店保留逻辑](../internal/app/webui/app.js#L101)、[保存后的行为](../internal/app/webui/app.js#L188)。

### 导出当前筛选不等于备份全部记录

优先级：P2。证据：原生界面、代码与隔离 API 实测。

没有个人记录时，页面仍显示完整内置曲线和“导出我的记录”。本轮导出接口返回 `HTTP 200`、0 字节。存在个人记录时，该按钮又隐式带当前门店、日期等筛选；设置里只有近一年导出，也没有恢复入口。

建议：图表按钮叫“导出当前筛选”，零条个人记录时禁用并简短说明；设置提供“备份全部记录”，后续配套导入与重复数据处理。个人数据与内置历史继续分开，不为避免空导出而混入内置历史。

代码：[隐式筛选](../internal/app/webui/app.js#L121)、[空导出](../internal/app/local_records.go#L234)、[设置中的导出](../internal/app/webui/index.html#L77)。

### 实时叫号会一直停在旧值

优先级：P2。证据：代码确定；本轮能正常读取公开排队接口。

选过门店后，长时间停留、切走再回来都不会自动刷新。页面仍显示“当前叫到”“可线上取号”，仅有小字更新时间和手动刷新按钮；唯一的定时刷新只作用于记录页。

建议：进入取号页、从后台恢复时刷新，停留时低频更新。失败后保留旧值但标明“未更新”，不要把旧值继续当当前状态。

代码：[返回页面不刷新](../internal/app/webui/app.js#L70)、[实时面板](../internal/app/webui/app.js#L193)、[定时器范围](../internal/app/webui/app.js#L271)。

### “想几点吃”的路程输入没有参与取号前建议

优先级：P2。证据：代码与纯模拟验证。

路程会触发校验和重新估算，但没有传给取号时间建议接口，也没有影响其展示；填 0 和 120 分钟得到相同请求与文案。取到号码后，另一个号码预测接口才会使用路程，不能说整个功能完全没用。

建议：要么在这里计算“何时出发/能否赶上”，要么移到取号后的出发建议中，避免让用户填写当前步骤不使用的信息。保留已有的“现在取号，不是预约某时间”的确认文案。

代码：[取号前只校验](../internal/app/webui/app.js#L214)、[取号后才传入](../internal/app/webui/auth_ticket.js#L70)、[明确非预约](../internal/app/webui/auth_ticket.js#L11)。

### 手机认证说明和实际操作对不上

优先级：P2。证据：代码确定，导入阻断已用纯模拟复现。

iPhone 页面要求点击已不存在的“我已装好证书，验证一下”；安卓页面指向不存在的“拿通行证第 4 步”。安卓用户即便找到“已有抓包凭证”，运行中的手机捕获也会阻止导入。停止又只能关闭整个弹窗，关闭会清掉已粘贴内容。

建议：先区分 iPhone/安卓；需要手动导入的路径不先启动手机代理。提供独立“停止连接”按钮，停止不清空输入，让手机说明和桌面控件使用同一套名称。

代码：[旧手机说明](../internal/app/mobile_auth_capture.go#L431)、[导入阻断](../internal/app/webui/auth_ticket.js#L167)、[关闭清空](../internal/app/webui/auth_ticket.js#L146)。

### 捕获成功与认证可用混在一起

优先级：P2。证据：代码与纯模拟验证。

凭证字段收齐但只读验证失败时，后端已记录失败，前端仍可能显示“凭证已保存在本机”和完成按钮。返回取号后又因凭证过期要求重新连接，用户看不到失败原因。查询已有号码遇到凭证失效时，也没有更新认证健康状态，只弹一个短暂错误提示。

建议：明确区分“已收到凭证”“验证通过”“验证失败”；失败原因留在弹窗中，并提供重试或换方式。认证结束要回到用户原先的查询动作，但绝不自动提交取号。

代码：[完成判定](../internal/app/webui/auth_ticket.js#L139)、[覆盖失败信息](../internal/app/webui/auth_ticket.js#L142)、[查询没有更新认证状态](../internal/app/web_engine.go#L673)、[认证后的返回动作](../internal/app/webui/auth_ticket.js#L160)。

### 手机打不开二维码时缺少电脑端退路

优先级：P2。证据：代码确定；实际网卡组合未实机验证。

后端能返回多个局域网地址，界面却只展示第一个。VPN/虚拟网卡地址不可达时，用户连说明页都打不开。完全找不到局域网地址时还会生成 `127.0.0.1` 二维码，手机无法借此访问电脑。

建议：电脑端直接提供“手机打不开？”和地址切换；无可用局域网时直接提示，不生成回环二维码。网络检查不要只放在手机打不开的页面里。

代码：[回环兜底](../internal/app/mobile_auth_capture.go#L113)、[第一个二维码](../internal/app/mobile_auth_capture.go#L166)、[只展示首个地址](../internal/app/webui/auth_ticket.js#L120)。

### 暂停记录不是退出后台

优先级：P2。证据：代码确定；Windows 覆盖安装的具体提示未实机验证。

“暂停记录”只关闭采集配置，不结束后台进程；关闭窗口也会保留它。README 要求升级前停止旧后台，但普通用户在界面找不到这个操作。Windows 下正在运行的旧 EXE 还可能妨碍替换程序。

建议：保留关窗口继续记录，增加一个明确的“退出应用及后台记录”，不要靠用户打开命令行或任务管理器。退出不删除数据，也不偷偷修改自启动偏好。

代码：[暂停只改配置](../internal/app/queue_service.go#L186)、[只有 CLI 停进程](../internal/app/queue_service.go#L232)。

### 升级后自启动可能仍指向旧程序

优先级：P2。证据：代码确定；系统登录启动未实测。

自启动保存当前程序的绝对路径，但状态只检查注册项是否存在。Windows 下载新版带版本号的 EXE、删除旧文件后，仍可能显示自启动已开启；保留旧文件则可能继续启动旧版本。macOS 移动应用也有同类风险。

建议：启动时检查目标文件是否存在、是否指向当前程序。异常时显示“需要更新自启动位置”，由用户一键修复，不能仅靠勾选状态表示健康。

代码：[Windows 只检查注册项存在](../internal/platform/platform_windows.go#L572)、[保存绝对路径](../internal/platform/platform_windows.go#L588)、[macOS 状态检查](../internal/platform/platform_darwin.go#L345)。

### 选店和视觉细节可以更直接

优先级：P3。证据：原生窗口实测与代码。

- 搜“深圳”会出现位于青岛“深圳路”的门店。增加城市筛选，或优先匹配城市，把地址全文匹配放后面；已选门店可以固定在顶部。
- macOS 的下拉框明显比旁边输入框矮，字号和点击区域也不统一。需要按实际 WebKit 渲染统一控件，而不是只验证 Chromium 截图。
- 设置里“开源许可”折叠后仍占据整块大卡片。并入版本/关于区域，把主要空间留给数据、账号和应用状态。
- 数据目录目前只显示路径。对本地记录工具，“打开数据文件夹”和完整备份/恢复比让用户理解目录字符串更有用。

代码：[地址全文匹配](../internal/app/queue_live.go#L303)、[选择器样式](../internal/app/webui/app.css#L8)、[设置结构](../internal/app/webui/index.html#L75)。

## 辅助访问

已有的键盘焦点描边、表单标签、跳转主内容入口、图表滑块和减少动画支持值得保留。

需要补查两点：每 30 秒会重建图表和下拉框节点，可能打断键盘焦点及读屏；本轮 macOS 辅助访问抓取中，部分确认/认证弹窗的可见控件未出现在树中。后者可能受抓取工具影响，不能直接判定 VoiceOver 不可用，需实机读屏复核。没有做完整无障碍合规结论。

代码：[无条件重绘](../internal/app/webui/app.js#L271)、[图表节点替换](../internal/app/webui/record_chart.js#L82)。

## 建议顺序

1. 先修数据裁剪和取消对象不一致，避免丢记录、误取消。
2. 修认证断点、实时状态过期、自启动位置校验，确保正常使用和升级不断。
3. 调整首屏顺序、选店与导出，把记录主流程接顺。
4. 最后统一控件尺寸、设置布局和键盘刷新行为，保留现有红白风格。

## 验证边界

- 原生界面使用全新隔离数据目录，只保存了测试门店选择；没有启动真实采集、自启动、证书安装、系统代理、微信认证、取号或取消。
- 已实测公共门店搜索、公开排队读取、空个人记录导出；现有 `node scripts/test-webui-records.mjs` 通过。额外纯模拟验证覆盖取消请求未带对象、手机捕获期间导入阻断、认证失败被显示成完成、取号前路程无效。
- Windows 完整界面、手机证书兼容性、窄窗口、断网、真实取号和取消不算通过。本轮未执行自动化浏览器场景；不能把此前发版的测试结果当作本轮证据。
- 没有修改业务代码、提交或发版。建议是下一轮改动范围，不是已经完成的修复。
