# 离线历史数据包

## 使用方式

首页默认展示内置历史，不需要账号或网络连接。按门店、日期范围、日期类型、具体日期查看；关闭“包含历史数据”后只统计本机采集，选择保存在 `record_view.json`，重启保持。

默认曲线是“叫到几号”，可切换“等多久”。鼠标移到点上、键盘选点或拖动时段，都会显示对应时段的叫号中位数、历史范围和样本天数；查看单日则显示当日记录。号码与等待分钟不混用纵轴。

历史包固定在代码中，不随应用启动、构建或发布重新下载。未来只有维护者主动替换文件，新的安装包才会携带新版本。截止时间始终来自包内元数据，不使用编译日期或今天的日期。

内置历史只参与“排队规律”图表，不进入个人模型、取号时间预测、已保存记录数、采集门店、自启动或“导出我的记录”。同店、同日、同半小时优先采用本机最后一条记录；即使这条本机记录显示未营业或等待未知，也不回退到历史值。

完整元数据、压缩大小、SHA-256 和质量计数见 `internal/app/data/queue-history-v1.manifest.json`。解包器和回归测试检查重复键、引用门店、时间范围、字段白名单及清单一致性。数据包损坏时只显示本机记录并提示，不去线上补取。

## 包格式

`queue-history-v1.json.gz` 内是 JSON，格式独立版本化。记录字段是统一公开快照的最小投影，不是个人采样文件；缺失值显式为 `null`，禁止直接追加进旧的整数型本机 JSONL。

- 信封：`version`、`id`、`source`、`timezone`、`bucket_minutes`、`first_at`、`cutoff_at`、`exported_at`、`quality_note`。
- 门店：`id`、`name`、`city`、`area`。
- 记录：`store_id`、`collected_at`、`date_type`、`store_status`、`wait_minutes`，新增可选且可空的 `display_called_no`。旧包缺少叫号字段时仍可读取，只显示等待曲线，不推算叫号。
- 唯一粒度：门店 + UTC+8 自然日 + 半小时起点。`collected_at` 保留实际采集时间，不挪到窗口起点。
- 日型：本次导出的节假日/调休覆盖表优先，其余沿用应用的周末窗口定义。

`/api/records` 返回协议版本 2：`available_stores` 是可分析门店，`stores` 始终只含个人原始快照摘要；`local_samples`、`history_samples` 是所选范围的有效等待半小时代表值数。`points` 是等待 P50/P80，`called_points` 是叫号 P20/P50/P80（`lower`、`median`、`upper`），各点带独立 `days` 和 `samples`；`called_local_samples`、`called_history_samples`、`called_days` 为叫号自己的覆盖统计。两类指标分别处理缺失，不把缺叫号的日期算入叫号分母。

所有曲线均聚合每日代表值，避免 5 分钟本机采样获得六倍权重。本机最后一条叫号为 0 时，该桶不回退到历史或之前的叫号。`dates` 为当前门店、范围和日型下有有效等待或叫号的日期，倒序返回。时间标签明确显示半小时窗口（如 18:00–18:29），不把窗口末次观测当成 18:00 整点事实。缺失时段的线与范围带都断开，不插值填充。

各时段的有效日期集合可能不同，缺失、不同日型或实际号段变化会让跨日中位曲线出现回落；不强行改成递增曲线，不把它当作某一天实际的叫号轨迹。需要看连续的一天时选择具体日期。

`days=all` 或省略表示全部历史；数字范围按今天向前计算，不以历史截止日冒充今天。`date=YYYY-MM-DD` 与范围、日型取交集。`/api/records/export` 仍只导出原始本机快照，不导出图表代表值或历史包。

## 维护者更新

先配置只读凭证，显式运行一次：

```bash
node scripts/export-history-bundle.mjs --config /absolute/path/read-only-config.json
```

配置字段为 `database_url`、`auth_token`，也支持 `SUSHIRO_HISTORY_DATABASE_URL`、`SUSHIRO_HISTORY_DATABASE_TOKEN` 环境变量。不把 token 放进命令行、代码、包或日志，不将含凭证的配置提交到仓库。

导出只执行预设的 SELECT 查询，先固定原始记录的最大 ID 和截止时间，分周读取、校验、压缩。运行前应确认源表没有并发历史重写；它不是跨多次 HTTP 请求的数据库事务快照。脚本输出目录默认为 `internal/app/data`，可以用 `--out` 指定临时目录先核对。

替换包时一起更新清单和本页覆盖说明，再运行：

```bash
node --test scripts/test-history-export.mjs
go test ./internal/app -run 'TestCalled|TestHistory|TestEmbeddedHistory|TestRecordView|TestLocalRecords|TestLocalHistory'
```

脚本不接入 CI、构建或 Release，也不会恢复桌面端数据库客户端。未来在线提供者仍须遵循 [统一数据协议](local-data-contract.md)，不能向用户分发数据库 token。
