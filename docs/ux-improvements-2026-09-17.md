# 日常使用体验调整

## 本轮交付

1. 首页集中于选店取号，增加三个简短步骤。已有号码、使用帮助和本机分析作为次要入口；界面模式放在设置，降低顶部拥挤。
2. 导航统一为选店取号、到店预测、我的号码。预测先给门店和号码输入，提醒、采集、原始配置按需展开。
3. 选店弹窗支持单选或多选、地址搜索、加载失败重试、空选择保护和已选摘要。搜索回车不会误确认旧门店。
4. 取号前可以直接改人数、桌型和门店。首次认证保留本次人数和门店，完成后再次明确确认；提交中、结果和不确定状态有独立反馈。
5. 本机分析先选门店再开启，暂停按钮直接可见。样本数、覆盖天数和自启动状态为主要信息，技术状态折叠。
6. 补齐表单标签、对话框标题、错误播报、键盘焦点循环和返回焦点；窄屏加大触控区域，选店列表与底部确认分离滚动。

## 同时修复

- 全国门店请求失败后缓存空数组，后续无法正常重试。
- 单选门店仍显示复选框、空选择能直接确认、搜索回车可能确认旧选择。
- 快速切换门店时旧实时请求覆盖新门店；移除关注门店后没有同步本地选择。
- 只因门店营业，就错误显示线上可取号。现在区分营业与线上取号状态。
- 没有采集配置或配置损坏时默认开启持续采集。现在需要显式启用，已有配置不变。
- 暂停服务后，先发出的状态查询可能把页面覆盖回运行中。

## 验证边界

通过 40 项 JavaScript 测试（39 项前端隔离测试、1 项 Worker 停用检查）、嵌入页面及 JavaScript 语法检查、`go test -race ./...`、`go vet ./...`、`go build ./...` 和 `git diff --check`。模板检查覆盖闭合标签和重复标识，测试均不发送真实取号或通知。

没有启动本地服务、截图评审或真人可用性测试；没有进行 Windows / 手机认证实机验收。响应式和无障碍改进是实现与模拟交互验证，不等于浏览器视觉验收。凭证获取依然受微信代理和证书策略影响，不能宣称免配置扫码登录。

对应规格：`specs/010-everyday-usability/`，T01 至 T06。前一轮本地化、服务和认证改动保持不变，线上只读 key 继续不处理。
