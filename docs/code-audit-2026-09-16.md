## Windows 排查

不能用“Windows 登录失败”直接推断唯一根因。本轮修了确定的字段解析、超时、状态误报、重置竞争、代理回滚和时区问题；没有证据证明所有 Windows 微信版本都能被代理捕获。

| 阶段 | 当前行为 | 真机需要的脱敏证据 |
|---|---|---|
| 入口 | 不再断言 PC 微信一定抓不到，保留尝试入口，优先手机或导入 | Windows/微信版本、架构、选择的入口 |
| 证书 | 用户库与机器库检查，机器库仍需 UAC | 阶段、是否授权、返回值、证书指纹，不能提供私钥 |
| 代理 | 当前用户 PAC/手动代理事务；不触碰机器级 WinHTTP | PAC 是否被读取、实际端口、CONNECT/TLS 是否出现 |
| QUIC | 普通权限可能无法设置防火墙规则，失败显示警告，不伪装成功 | 警告内容、是否走 UDP 或绕过系统代理 |
| 字段 | 支持 GET/POST 字段；缺失项有明确出口 | 字段完成度、请求方法/路径，不提供 token/手机号原文 |
| 认证 | 已保存、尚未验证、认证查询通过、失效分别显示 | 分接口状态码与脱敏错误 |

建议先判断请求是否经过代理，再看 TLS、字段和官方认证；不要继续把不同故障都归结为“重装证书”。

## 页面与结构

本轮已收敛凭证向导、主页/设置健康状态、查号结果、提醒采集状态、停止中状态及定向预约摘要。凭证原文草稿只留页面内存，关闭或重置清除；旧 localStorage 草稿主动删除。确认框有对话框语义、键盘焦点圈定、默认取消和焦点返回，并处理重叠弹窗。

这不是全站视觉重做。概览信息密度、预测页信息分组、教程重复、日历内联提交进度仍可继续优化，但需要截图/实际浏览证据，不能以源码检查冒充视觉验收。

Go 分包方向保持 `app/api/core/proxy/platform/notify`。新增认证提交边界、统一运行启动入口、可注入代理事务和独立 MCP 资源释放模块，避免继续把所有逻辑塞进 HTTP handler。前端仍使用 Go embed，不引入 Node 运行时。

仍存在的结构债务：app 包和若干文件偏大，dot import 隐藏类型归属，前端共享全局状态较多；个人预约状态事务目前只保证单进程。公开数据和提醒已补跨进程锁，但这不等于所有业务状态都已支持多进程写入。后续应逐步拆页面模块，不宜在此次安全修复里整仓重写。

## 简洁主路径与本机服务

按最终产品目标追加规格 `009-simple-ticket-local-service`，不改变“认证只能只读验证”的边界：

- 首页主按钮为选店取号，我的单据在简化版可见；选店、人数和桌型后，缺凭证才打开认证向导。获取完成恢复确认，不自动提交。Windows 优先手机引导，PC 捕获和粘贴保留为备选；证书/网络限制不冒充已消除。
- 取号请求失败或超时先引导查询当前号，不自动重试。已有号按官方真实门店展示；回调晚到不能恢复已取消的认证草稿或轮询。
- 新 `quick_flow.js` 单独承载主路径，移除无调用的旧看板认证采集开关；高级采集明确命名为预约时段采集。
- 新独立公开服务和用户级登录自启动，不读取个人凭证、不启动订单调度器。旧 sampler 后台入口兼容为只读服务；预约计划须保持应用运行，不依赖采集服务执行。
- 桌面与服务共享采集时间及 OS 文件锁，主流程结束后自动恢复。JSONL 写入/裁剪与提醒状态分别互斥；部分采集被打断也保留已收集快照。
- `queue_model.json` 保存版本化本机分位数模型，展示样本、覆盖日期和更新时间；文件/节假日变更或超过一天后失效。门店维度不足仍按局部样本判断，不以总样本量宣称精度。

追加回归为 `queue_service_test.go`、`queue_model_test.go`、`platform/file_lock_test.go`、`scripts/test-webui-quick-flow.mjs`。自启动操作使用注入替身，未在当前系统安装或启动服务；文件锁验证含独立测试子进程。用户级自启动、Windows 微信真实认证和界面渲染仍需实机验收。
