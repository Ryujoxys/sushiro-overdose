# 实施方案

## 数据包

维护脚本 `scripts/export-history-bundle.mjs` 查询已确认的公开门店维度、历史快照、早期逐日代表值和节假日日历。只执行 SELECT，按时间分批读，固定数据截止边界。输出压缩 JSON 及质量摘要，凭证仅在脚本内存中使用，不嵌入应用。

包协议独立版本 1，UTC+8、半小时粒度，包含采样原时间、门店、可空等待分钟和营业状态。早期聚合中的 NULL 保持未知。每日代表值不得误称原始快照数，也不对分位数再次求平均。

## 应用

- `history_bundle.go` 用 `go:embed` 只读载入固定包，校验版本、字段、时间、门店、数值与唯一性。
- `record_view.go` 读写独立的本机展示设置，并合并半小时代表值。只在内存使用历史包，不写进个人 JSONL 或模型。
- `/api/records` 扩展来源计数、可选门店/日期和数据包元信息；旧本机快照导出保持不变。
- 前端保存历史开关，首次自动展示有数据的店，移动端保留可读坐标轴。

## 文件所有权

- `internal/app/data/queue-history-v1.json.gz` 与旁边 manifest：仅维护者导出脚本写，应用只读。
- `record_view.json`：仅设置 POST 写，GET 缺文件时采用默认值，不创建文件。
- `queue_baseline.jsonl` 与 `queue_model.json`：不被内置数据读入流程改写。
- 不读旧云端凭证文件；导出脚本显式指定该文件仅用于维护者这一轮数据导出。

## 验证

真实数据检查记录覆盖、时间边界、重复键、空值、异常等待值、孤立门店和包大小。Go 测试验证本机覆盖历史、不混入个人计数、关闭不回退、查询无网络及无文件副作用；Node 和浏览器检查覆盖首次曲线、日期过滤、关闭/重开及小屏。
