# 实施方案

## 职责

- 数据层停止破坏性原始记录裁剪，维持现有 JSONL 文件协议和读取路径；聚合模型仍按既有范围构建。
- 取消接口使用服务端签发的账号及票据绑定凭据，并在同一认证生命周期锁内进行只读核对及显式取消。不向前端暴露账号凭证。
- 认证页面明确收到、验证成功、验证失败三种状态；手动导入与捕获停止分开；保存返回意图。
- 首页与搜索控件由前端维护；后台刷新采用版本/请求锁和未变化不重绘，保持键盘焦点。
- 实时排队继续使用公开只读接口；路程必须参与建议，或移到实际使用它的号码预测步骤。
- 后台退出仅停止同一数据目录的记录进程。自启动异常只能提示及经用户确认修复，不自动修改系统设置。

## 安全约束

保持 Host、Origin、CSRF、桌面桥接白名单和通知隔离。所有新增状态操作只修改当前数据目录或经过用户明确确认的自启动项。查询失败不执行远端变更，不自动重试取号或取消。

## 验证

- Go 数据保留、导出、账号切换、取消不匹配、认证健康、后台退出和自启动状态单元测试。
- Node 前端状态测试覆盖搜索、首屏、导出空状态、认证返回、失败提示和刷新行为。
- 常规与原生构建、静态检查；能运行的隔离测试均使用测试目录与模拟通知。
- UI 检查保留现有视觉，检查窄窗口、键盘与弹窗状态，不使用真实账号或代理。

## 取舍

先去除自动删除，避免分月迁移同时改动全部读写路径造成漏记录。长期文件增长与分月存储后续单独设计，不能以性能优化为由删除原始记录。
