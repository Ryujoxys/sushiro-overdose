# 实现计划

## 架构

- 将 Web 路由注册与服务生命周期拆开，启动时直接持有监听器，避免探测端口后被其他进程抢占，以及页面早于服务启动。
- `desktop` 构建标签接入 Wails v2 稳定版。macOS 使用 WebKit，Windows 使用 WebView2；缺少运行时时提供官方安装引导。
- 原生桥仅转发本机服务的相对 API 路径，限制方法、请求大小、响应大小和超时；保留 HTTP 的 Host、Origin、CSRF 校验。不对远程页面开放绑定。
- 原生保存接口仅接受记录导出和脱敏诊断包两种资源，目标路径由系统对话框选择。
- 启动前用现有跨平台 OS 文件锁互斥；另存权限受限的临时会话描述，使用随机令牌唤起已有窗口。第二实例不执行配置迁移、代理清理或采集启动。
- 关闭界面取消其 context、停止认证并关闭本地 HTTP；不停止独立采集子进程，不修改用户记录配置。

## 架构例外

原“所有 Go 代码零外部依赖”调整为“业务核心保持标准库，桌面适配层允许固定版本 Wails 及其传递依赖”。升级 Go 最低版本以匹配稳定版 Wails。常规 CLI 构建不包含 WebView 依赖，不强制用户安装 Node.js。

## 数据

业务数据格式不变。增加 `desktop.lock`、`desktop_session.json` 和 Windows 的 `webview/` 缓存目录；会话文件不存个人凭证。关闭时删除会话文件，不删除 OS 锁文件。隔离预览仍使用 `SUSHIRO_DATA_HOME`。

## 分发

DMG 和双击 EXE 使用原生构建；压缩包保留 CLI/浏览器版本。macOS 原生二进制需要 CGO 和系统 SDK，两种架构合并为 Universal。Windows 保留干净 manifest 和 GUI 子系统。新 Release 全部产物及校验表完成后才公开。

## 验证

单元测试覆盖桥接白名单、超时、取消保存、会话令牌和互斥；前端测试覆盖原生与浏览器两条通信路径。运行隔离 Go/Node 测试、浏览器回归、macOS 原生窗口检查和多平台构建。发布后验证 Release 附件，再删除旧 Release，不删除 tag。
