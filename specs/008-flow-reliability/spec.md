# 主流程可靠性修复

## 目标

修复静态审查发现的 F1 至 F9：验证不取号、查号不重复通知、取号后提醒继续运行、捕获有明确边界、停止与重置无旧任务回写、凭证状态如实展示、Windows 代理失败可恢复、发行包自带 MCP 源码。

## 边界

- 不部署、不调用真实预约或取号、不安装证书或修改当前机器代理。
- 自动测试必须隔离用户目录、官方网络和系统通知。
- 不承诺仅凭源码就验证 Windows 微信的实际网络行为；交叉编译不等于真机验证。
- 本轮不重新开放云数据库，也不大规模重写视觉设计。
- 自动检查工作流改为手动触发，发布流程不再执行全量测试；本地回归、通知隔离和 Windows 产物清单校验保留。

## 验收

1. 凭证验证只读；接口故障和未验证不能标成全部可用。
2. 重复 GET 查号不修改取号计划、不发送通知。
3. 无凭证或已取到号时，公开数据采集仍能评估已启用的叫号提醒。
4. 捕获超时给出缺失字段，不引导用户为了验证创建真实预约或排队号。
5. 停止未完成时拒绝新任务；定向预约目标与启动原子绑定。
6. 重置使全部捕获会话失效，旧会话不能保存凭证或停止新会话。
7. 仅保存字段的状态是未验证，只读认证成功和认证失败单独表达。
8. Windows 修改代理前保存原配置，失败回滚，异常退出后可恢复。
9. 裸可执行文件无需旁边有源码仓库也能找到内嵌 MCP 包。
